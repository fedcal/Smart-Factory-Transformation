<open_q5_resolution>
**Open Q5 from RESEARCH.md** (citation `source_uri` full PG lookup vs shape-only validation) — **resolved: full PG lookup, audit-friendly** (locked in CONTEXT.md L284).

Rationale:
1. **Hallucination mitigation**: T-V7-llm-hallucination is the highest-impact threat for RCA — an LLM that invents `source_uri="doc://nonexistent"` would produce a chain that *looks* citation-grounded but is actually fabricated. Shape-only validation cannot catch this.
2. **Audit-friendly**: the audit row carries the validated chain; downstream forensic review needs only the chain itself (not a re-lookup) to trust citations exist.
3. **Performance acceptable**: 5 WhyStep × ~1-3 citations each = max ~15 PG round-trips per RCA invocation; sub-50ms total against indexed `documents.source_uri`. RCA is not high-frequency (operator-initiated, typically <10/h per shift).
4. **Failure mode**: if PG `documents` table doesn't yet have a `source_uri` column / index (Phase 5 baseline), discover at implementation time + document — the validator implementation depends on Phase 5 D-65 schema. If absent, the validator falls back to shape-only with a hard structlog ERROR (NOT silent) + a TODO to add the column. Decision recorded here: prefer full lookup; degrade to shape-only with loud warning if Phase 5 schema gap.
</open_q5_resolution>
