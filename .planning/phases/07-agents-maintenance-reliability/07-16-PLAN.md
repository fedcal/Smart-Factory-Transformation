<objective>
Close the DowntimeAnalyzer (MNT-04) runtime defects spanning the gateway, OEE math, and the agent.

- WR-03 (BLOCKER): the gateway `post_da_report` builds the state dict with `body.window_start.isoformat()` / `body.window_end.isoformat()` (lines 646-647). asyncpg requires Python `datetime` objects for TIMESTAMPTZ params, so every `/report` call raises `asyncpg.exceptions.DataError`.
- WR-04: `compute_pareto` computes `grand_total = sum(r[1] for r in trimmed)` (oee.py line 320) where `trimmed = sorted_rows[:top_n]`, so the last entry's `cumulative_percent` is always 100% regardless of true coverage.
- CR-05: `by_asset=True` (agent.py lines 228-252) iterates over every asset sequentially (3 DB queries each) with no cap or concurrency limit (DoS vector), and `compute_quality_cross_cluster` is called twice for the aggregate path (once inside compute_oee at line 203, once explicitly at line 214).

Purpose: Restore SC-4 — "DowntimeAnalyzer calculates OEE decomposition (A, P, Q) and produces a Pareto of downtime causes from the event store" — as a functional /report endpoint with correct Pareto math and bounded resource use.
Output: Fixed gateway router + oee.py + agent.py, plus regression tests that fail against current code and pass after the fix.
</objective>
